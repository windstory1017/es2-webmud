# 當鋪清單（list）無法顯示：問題報告與修正方案（2026-10-25）

> 使用者回報（2026-10-25）：線上主機的當鋪打 `list` 完全沒有反應，像是指令無效。
> 相關程式：`source/upstream/mudlib/std/room/hockshop.c`（三間當鋪共用）、`daemon/misc/hockshop_d.c`（共用倉庫）。
> 相關設計：`docs/PAWNSHOP_NETWORK.md`（當鋪連線，2026-10-23）。
> 狀態：**原因已查明，修正方案待使用者決定（#15），程式尚未修改。**

## 一、現象

| 項目 | 內容 |
|---|---|
| 發生地點 | 線上主機的五堂鎮當鋪（`d/wutang/pawnshop`）、喬陰縣當鋪（`d/qiaoyin/pawnshop`）；三間共用倉庫，李家村應相同 |
| 回報身分 | 巫師帳號 |
| 畫面 | 打 `list` 後什麼都沒有顯示，沒有錯誤訊息 |
| 紀錄 | 主機 `mudlib/log/debug.log` 有 5 筆相同錯誤（2026-10-25 17:23～17:50） |

## 二、原因

錯誤紀錄：

```
*Printable strings limited to length of 8192.
do_list() at /std/room/hockshop.c:231 (object d/wutang/pawnshop)
start_more_if_needed() at /feature/user/more.c:72
write() at /adm/simul_efun/message.c:71
receive_message() at /feature/char/message.c:52
```

1. 遊戲一次送給玩家的文字，最多 8192 個字元（位元組；中文字一個佔 3）。
2. `do_list()` 把整份清單組成一大段文字，再用 `start_more_if_needed()` **一次送出**。
   這個函式名稱看起來會分頁，實際上只是把全部內容一次 `write()`，不會分頁。
3. 當鋪連線（2026-10-23）後三間當鋪共用倉庫，貨物累積很快。錯誤當時清單開頭就有：

   ```
   1  短劍 (Short sword)   共 245 把   十八兩
   2  布衣 (Cloth)         共 343 件     四兩
   3  匕首 (Dagger)        ……
   ```

   每一項約佔 100 個字元，**大約 70～80 項就會超過上限**。
4. 超過上限時送出失敗、程式中斷。這個遊戲出錯時不會在玩家畫面顯示錯誤，所以看起來就像指令無效。
5. **巫師更容易超過**：巫師的清單最後還會逐件列出「典當中的物品」，比一般玩家長。
   一般玩家看不到這一段，但上架貨物一多也會超過。

## 三、檢查時一併發現的問題

| # | 問題 | 影響 |
|---|---|---|
| A | `value_string()` 遇到價值小於 1 時，把價值改成 1 之後**沒有回傳文字**，接著對齊時出錯 | 倉庫裡只要有一件算出來價格為 0 的貨，整份清單一樣不會顯示（目前賣斷、典當都會擋掉價值 0 的物品，發生機會低） |
| B | `list <名稱>` 篩選後，編號重新從 1 開始；`buy <編號>` 卻照**完整清單**的編號 | 玩家照篩選後的編號買，可能買到別的東西，錢照扣 |
| C | 巫師的典當物清單一件一行，不合併 | 典當物多時清單非常長 |
| D | 倉庫只限制「最多 200 項」，**沒限制每一項的件數**（例如短劍 245 把、布衣 343 件，每件都是獨立物件） | 佔用主機記憶體；重開伺服器後才會清空 |

## 四、修正方案（#15，待使用者決定）

| # | 內容 | 建議 |
|---|---|---|
| 15-1 | `list` 改為分段送出：逐行累積，每段控制在上限以內（例如 6,000 字元）就先送出，不論貨物多少都能完整顯示 | **必修** |
| 15-2 | `value_string()` 補上價值小於 1 時的回傳（顯示一文錢） | 建議 |
| 15-3 | `list <名稱>` 篩選後仍顯示完整清單上的編號，與 `buy <編號>` 一致 | 建議 |
| 15-4 | 巫師的典當物清單，相同物品合成一行並標數量（例如「短劍 共 12 把」） | 選擇 |
| 15-5 | 每一項貨物設件數上限（例如 20 件），超過的新貨直接丟掉不上架（賣出的玩家照常拿錢） | 選擇；上限數字由使用者決定 |

## 五、更新方式

- 改到 `std/room/hockshop.c`（`std/` 底下），依 `docs/UPDATE_RESTART_GUIDE.md` **需要重開遊戲**：
  `bash ~/es2-webmud/deploy/oracle/update.sh`
- 若只改 15-5 而動到 `daemon/misc/hockshop_d.c`，同樣建議一般更新（倉庫在記憶體中，重開會清空現有貨物）。
- 重開後共用倉庫清空，清單回到很短的狀態；不修 15-1 的話，貨物累積後還會再發生。
